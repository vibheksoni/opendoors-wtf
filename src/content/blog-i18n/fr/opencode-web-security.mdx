## La meilleure alternative ?

J'utilise **OpenCode** depuis peu et, honnêtement, je trouve que c'est une alternative supérieure à Claude Code sur bien des points. Il prend en charge plusieurs fournisseurs de LLM (Ollama, OpenAI, Anthropic, etc.), il est open source et il me semble plus rapide. Pouvoir changer de modèle à la volée en fait un outil redoutable pour le développement en local.

Cependant, comme beaucoup d'outils pour développeurs dans ce domaine, il propose un mode « Web UI » (`opencode web`) qui transforme votre CLI en application accessible depuis un navigateur. C'est très pratique, mais cela ouvre une énorme faille de sécurité si vous n'y prenez pas garde.

## Le risque

Quand vous lancez `opencode web`, un serveur démarre. Si vous le liez à `0.0.0.0` (toutes les interfaces) pour y accéder depuis un autre appareil de votre réseau, vous exposez potentiellement une vulnérabilité d'**exécution de code à distance (RCE)** à tout Internet.

Comme pour l'interface web de Claude Code dont j'ai parlé précédemment, l'interface web d'OpenCode permet à l'utilisateur d'exécuter des commandes, de modifier des fichiers et d'interagir avec le shell. Sans authentification, quiconque trouve votre adresse IP devient administrateur de votre machine.

## Comment le sécuriser

Les développeurs d'OpenCode ont bien inclus un mécanisme de sécurité, mais encore faut-il l'utiliser.

### 1. Définir un mot de passe
Vous pouvez verrouiller l'interface web en définissant un mot de passe. Cette simple étape empêche les accès non autorisés.

Lancez cette commande avant de démarrer le serveur web :
```bash
opencode --set-password <your-strong-password>
```
*Vous pouvez aussi définir la variable d'environnement `OPENCODE_SERVER_PASSWORD`.*

### 2. Ne pas l'exposer à Internet
Sauf si vous avez une raison très précise (et un VPN ou un tunnel), ne redirigez pas le port d'OpenCode vers l'Internet public. Gardez-le sur `localhost` (`127.0.0.1`) ou strictement au sein de votre réseau local de confiance (`LAN`).

## Conclusion

OpenCode est un outil formidable que je recommande vivement pour sa prise en charge multi-modèles et sa rapidité. Mais « puissant » veut dire « dangereux » si l'on retire les garde-fous.

Ne laissez pas votre assistant de code devenir la porte d'entrée d'un attaquant. Définissez un mot de passe.
