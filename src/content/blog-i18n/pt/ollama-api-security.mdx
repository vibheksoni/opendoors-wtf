## O problema

Ollama é um serviço de API popular que roda localmente na sua máquina, permitindo usar modelos de IA sem depender de infraestrutura de nuvem externa. Ele opera na porta **11434** e é acessível via `http://localhost:11434`.

Aqui está o ponto: o Ollama não tem autenticação nativa. Embora isso não seja uma vulnerabilidade no sentido tradicional, cria um risco significativo. Se a porta da sua máquina estiver exposta à internet, qualquer pessoa pode acessar o seu serviço Ollama e usar seus recursos sem permissão.

## O que pode dar errado

Sem autenticação e com uma porta aberta, um atacante poderia:

- Interagir com os seus modelos de IA
- Baixar os modelos que rodam na sua máquina
- Executar tarefas usando o seu hardware

Para desenvolvedores com máquinas de alto desempenho ou que rodam em provedores de nuvem, isso pode levar a um consumo de recursos significativo e a cobranças inesperadas.

## Como eu descobri isso

Enquanto explorava o comando `ollama serve`, percebi que o serviço já está rodando se o Ollama estiver instalado e ativo. Decidi verificar a escala dessa exposição usando o **FOFA**, um mecanismo de busca de ciberespaço.

Pesquisei por máquinas expondo a porta 11434 com uma consulta simples: `"Ollama is running" && port="11434"`. Escolhi essa assinatura específica porque, ao acessar o endpoint raiz (`/`) de uma instalação padrão do Ollama, ele retorna exatamente essa string confirmando que o serviço está ativo.

- Consegui interagir com endpoints expostos, baixar modelos e usar o hardware deles
- Muitas instâncias rodavam em setups de alto desempenho, provavelmente sem o conhecimento do dono

## Como proteger o seu serviço Ollama

Se você usa o Ollama, siga estes passos para proteger o seu serviço:

### 1. Lista de IPs permitidos

Use um firewall para restringir o acesso apenas a IPs confiáveis.

### 2. Adicione uma camada de autenticação

Implemente um wrapper ou serviço de proxy que exija autenticação antes de interagir com a API do Ollama.

### 3. Desative o acesso público à porta

Garanta que a porta 11434 não esteja acessível pela internet. Configure-a para permitir apenas acesso local.

## Conclusão

Isto não é sobre culpar o Ollama, e sim sobre entender os riscos de rodar serviços locais sem a configuração de rede adequada. Ao aplicar medidas básicas de segurança, você protege seu sistema contra acesso não autorizado e garante que seus recursos continuem sendo seus.
