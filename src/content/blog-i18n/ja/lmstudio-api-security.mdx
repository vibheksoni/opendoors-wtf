## 問題点

LM Studio は GUI ベースの強力なアプリケーションで、ローカル LLM を誰でも手軽に動かせるようにしてくれます。便利な機能として、ポート **1234** で OpenAI 互換 API を提供する**ローカルサーバー**が用意されています。

このサーバーを使えば、ローカルのモデルを他のアプリケーションから利用したり、ローカルネットワーク内で共有したりできます。しかし、多くの開発者向けツールと同じく、デフォルトでは安全性よりも使いやすさが優先されています。サーバーを有効にしたとき、特に適切なファイアウォールがない状態で "Serve on Local Network" をオンにすると、インターネット全体に向けて扉を開けてしまうかもしれません。

## 何が起こりうるか

LM Studio のサーバーはデフォルトでは認証を強制しません。マシンがインターネットに直接接続されていたり、ルーターがポート 1234 を転送していたりすると、攻撃者は次のようなことができます。

- **モデルへの問い合わせ:** あなたの計算リソースを使ってテキストやコードを生成されます。
- **電気代の増加:** GPU での推論が続くと、かなりの電力を消費します。
- **ロード済みコンテキストへのアクセス:** モデルが以前のセッションのコンテキストを保持している場合(実装によります)、機密データが理論上は漏れる可能性があります。

## どうやって見つけたか

「使いやすさ」を重視する設計思想が、他の開発ツールで見られるような意図しない公開につながっていないか確かめたいと思いました。LM Studio には、サーバーを有効にするための専用トグルが GUI にあります。

公開されているインスタンスを探すために、サイバー空間検索エンジンの **FOFA** を使いました。

LM Studio のサーバーレスポンスに特有のシグネチャを持ち、ポート 1234 を公開しているマシンを検索しました。使ったクエリは次のとおりです: `port="1234" && body="LM Studio"`。

## LM Studio インスタンスを守る方法

LM Studio のサーバー機能を使うなら、次の手順で安全を確保してください。

### 1. localhost のみにバインドする
別のデバイスから LM Studio にアクセスする必要が特にないなら、サーバーが `0.0.0.0`(すべてのインターフェース)ではなく `127.0.0.1`(localhost)で待ち受けていることを確認してください。LM Studio の GUI でサーバー設定を確認しましょう。

### 2. ファイアウォールを使う
どうしても "Serve on Local Network" を使う場合は、OS のファイアウォール(Windows Defender や macOS Firewall)やルーターを設定して、パブリックインターネットからポート 1234 への受信トラフィックをブロックしてください。接続は信頼できるローカル IP アドレスからのみ許可します。

### 3. 使わないときはサーバーを無効にする
最もシンプルな防御策は、オフにすることです。ローカルサーバーは、開発やテストで実際に使っているときだけ起動してください。

## まとめ

LM Studio のようなツールは AI の民主化を進めていますが、同時にクラウド級のセキュリティ上の責任をデスクトップにも持ち込みます。GUI のチェックボックス 1 つで、あなたのハードウェアが世界中に公開されてしまうことがあります。ローカルツールのサーバー機能を有効にするときは、必ずネットワーク上の公開状況を確認してください。
