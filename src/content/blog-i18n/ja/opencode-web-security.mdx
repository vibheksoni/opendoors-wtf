## より優れた代替ツールなのか?

最近 **OpenCode** を使っているのですが、正直なところ、多くの点で Claude Code より優れた代替ツールだと感じています。複数の LLM プロバイダー (Ollama、OpenAI、Anthropic など) に対応していて、オープンソースで、動作も速く感じます。モデルをその場で切り替えられる柔軟さは、ローカルでの開発において大きな武器になります。

ただし、この分野の多くの開発者向けツールと同じように、OpenCode にも CLI をブラウザベースのアプリケーションに変える「Web UI」モード (`opencode web`) があります。使い勝手の面では便利ですが、注意しないと非常に大きなセキュリティホールになります。

## リスク

`opencode web` を実行すると、サーバーが起動します。ネットワーク上の別のデバイスからアクセスするためにこれを `0.0.0.0` (すべてのインターフェース) にバインドすると、**リモートコード実行 (RCE)** の脆弱性をインターネット全体に晒してしまう可能性があります。

以前書いた Claude Code の Web UI と同じように、OpenCode のウェブインターフェースでは、コマンドの実行、ファイルの編集、シェルの操作ができます。認証がなければ、あなたの IP アドレスを見つけた人は誰でも、あなたのマシンの管理者になれてしまいます。

## 安全に使うには

OpenCode の開発者は、実際にセキュリティの仕組みを用意してくれています。ただし、それを自分で有効にする必要があります。

### 1. パスワードを設定する
パスワードを設定すれば、Web UI をロックできます。この簡単な手順だけで、不正アクセスを防げます。

ウェブサーバーを起動する前に、次のコマンドを実行します:
```bash
opencode --set-password <your-strong-password>
```
*別の方法として、環境変数 `OPENCODE_SERVER_PASSWORD` を設定することもできます。*

### 2. インターネットに公開しない
明確な理由があり、VPN やトンネルを使っている場合を除いて、OpenCode のポートを公開インターネットに転送しないでください。`localhost` (`127.0.0.1`) か、信頼できるローカルネットワーク (`LAN`) の内側だけで使いましょう。

## まとめ

OpenCode は素晴らしいツールで、マルチモデル対応と速さの点で強くおすすめします。ただし、安全装置を外してしまえば、「強力」は「危険」と同じ意味になります。

コーディングアシスタントを攻撃者の侵入口にしてはいけません。パスワードを設定しましょう。
